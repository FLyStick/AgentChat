AgentChat API 错误排查 FAQ V1.5
面向：后端开发、测试与线上值班工程师
更新日期：2026-07-02

1. 请求超时与连接错误
调用模型接口出现 ConnectError 时，首先检查网络代理、域名解析和目标服务端口。常见原因是模型API域名无法解析、本地网络被代理拦截、上游服务瞬时不可用或证书过期。连接错误会自动重试最多两次，重试间隔为1秒和3秒；连续三次失败返回统一错误码 LLM_CONNECT_ERROR。排查时先用 curl 直接请求健康检查接口，再检查日志中的具体异常。

2. Embedding 请求超时
Embedding 请求超时通常由长文档批量向量化、上游限流或单条文本过长引起。生产环境默认单批最多20条，单条文本超过8000字符会先截断再向量化。超时后服务对该批文本整体重试，重试仍失败时对应文件标记为待重导。排查步骤依次为：查看 Embedding 接口日志、确认文本条数和长度、检查上游配额、缩小批次后重新上传。

3. Rerank 服务不可用
Rerank 服务不可用时，检索链路会自动回退到向量召回原始分数，不会返回空结果。回退日志包含 Warning 字样，操作人员可通过日志数量评估失败比例。批量 Rerank 单次请求最多100条候选，超过数量会分批发送；单条候选超过1024字符会截断。排查时先测试 Rerank API 的连通性，再检查请求体是否包含非法字符。

4. Chroma 持久化目录异常
Chroma 数据默认存放在后端目录 `vector_db`，删除或切换目录前必须停止后端服务。持续运行期间直接删除目录会导致集合缓存失效、文件锁定和启动失败。切换 Chroma 目录后，需要重启后端并重新上传知识库文件；旧集合不会自动迁移。查询不到数据时，检查 `vector_db` 目录权限、磁盘剩余空间以及集合名称大小写。

5. SSE 流式接口事件结构
`/api/v1/completion` 使用 SSE 格式返回，事件均为 `data:` 前缀的 JSON。内容事件包含 `type=content` 和 `content` 字段，事件结束标识为 `type=done`。前端收到 `done` 事件后应停止接收、提交最终对话记录并渲染完整回复；收到 `error` 事件时应停止加载态并展示错误信息。前端不应依赖连接关闭事件判断成功，必须显式等待 `done`。

6. 知识库文件处理失败
知识库文件上传后处理失败，常见原因包括文件格式不支持、解析异常、Embedding 生成失败和向量写入失败。文件状态会停留在 `processing` 或变为 `failed`，失败原因记录在文件处理日志中。修复后可从文件列表重新触发处理，不需要重新上传。同一文件名重复上传会生成新文件记录，不会覆盖旧文件。

7. 对话接口返回空回答
对话接口返回空回答时，优先检查是否是模型输出被工具调用文本过滤。项目在工具调用场景会丢弃工具调用前的模型中间文本，只保留最终自然语言输出。若模型中途结束而没有最终回答，对话历史会记录空内容，前端应提示用户重试或更换问题。排查时对比原始模型日志与最终回答字段。

8. 多 Agent 路由未命中
主 Agent 未路由到子 Agent 时，先查看路由关键词命中记录和对话内容是否匹配预设路由词。路由依赖固定关键词，口语表达与预设词不一致时不会触发。配置多 Agent 后，需要确保 Agent 同时开启 `enable_multi_agent=true` 且子 Agent 已绑定工具、模型和知识库。路由日志位于后端日志的 `orchestrator` 模块。

9. 状态码与错误码对照
HTTP 400 表示参数校验失败；401 表示 token 无效或过期；404 表示资源不存在；422 表示请求体格式不正确；500 表示服务内部异常。业务错误码统一放在响应体 `status_code` 中：`200` 成功、`40001` 参数错误、`40101` 鉴权失败、`50001` 模型调用失败、`50002` 知识库处理失败。前端应根据业务错误码而非 HTTP 状态码做差异化提示。

10. 日志与问题定位步骤
线上问题排查先按调用链收集接口日志、模型日志和依赖服务状态。后端日志目录默认位于 `logs`，按天滚动保留30天。定位时先确认故障时间点，再按 request_id 聚合同一请求的全部日志行。修复后需要回归原始场景，并在 `docs/eval` 或测试用例中补充对应案例，避免同类问题再次发生。
